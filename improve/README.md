# improve/ — 스스로 고쳐 나가는 루프

> 사용자 지시(2026-10-11): 비슷한 인기 앱의 기능·UI·UX·불편한 점·속도를 조사해 **이 앱을 계속 개선한다.**
> 빌드는 집 PC 러너, 게시는 GitHub 릴리스. 권한은 전부 위임받았다 — 묻지 말고 진행한다.

대상은 **안드로이드 앱 `android-toss/`** (주력)과 그 앱이 붙는 **PC 서버 `web/`**.
`app.py`(Streamlit)·`android/`(옛 앱)는 건드리지 않는다.

## 폴더

| 파일 | 무엇 |
|---|---|
| `BACKLOG.md` | **할 일의 원본.** 상태(대기·진행·완료·보류)와 순서. 한 바퀴 돌 때마다 고친다 |
| `LOG.md` | 바퀴별 기록 — 무엇을 했고, 무엇을 확인했고, 무엇이 남았나 |
| `research/competitors.md` | 앱별 좋아하는 점·불만·출처 |
| `research/ideas.md` | 아이디어 원문(근거·파일 위치·크기). BACKLOG 의 `#번호`가 여기 번호다 |
| `build.sh` | 로컬 컴파일·빌드. 푸시 전에 반드시 통과시킨다 |

## 한 바퀴

1. **읽는다** — `BACKLOG.md` 맨 위 `다음` 항목, `LOG.md` 마지막 기록, `git log -5`.
2. **고른다** — 효과 높고 작은 것부터 2~4개. 서로 같은 파일을 건드리는 것끼리 묶는다.
   고르기 전에 **그 기능이 정말 없는지 코드에서 확인**한다(조사 문서가 틀린 적이 있다 — 아래 '배운 것').
3. **고친다** — `CLAUDE.md`·`SESSION_NOTES.md` 의 규칙을 따른다(주석 한국어, 한국식 색, 공통 부품은 `ui/Ui.kt`).
4. **확인한다**
   - `bash improve/build.sh compile` (코틀린 컴파일, 1분 안쪽) → 통과해야 다음으로.
   - 서버(`web/`)를 고쳤으면 `cd web && python test_ui.py` (가짜 시세로 직접 눌러 보는 검사).
   - 자기 diff 를 **깨뜨릴 방법을 찾는 눈으로** 다시 읽는다: 그리는 중 네트워크, 종목 전환 경합, NaN, 빈 목록.
5. **올린다** — conventional commit 으로 `main` 에 push.
6. **빌드·게시** — `gh workflow run android.yml -f publish=true -f notes="…"` (PC 러너 `HSYUNPC-stocks`).
   `gh run watch` 로 끝을 본다. 실패하면 그 바퀴 안에서 고친다.
   - 화면에 보이는 변화가 있는 바퀴만 게시한다. 내부 정리뿐이면 `publish=false`.
7. **적는다** — `BACKLOG.md` 상태, `LOG.md` 한 단락. 큰 구조가 바뀌었으면 `SESSION_NOTES.md` 도.
8. **조사를 보충한다** — 대기 항목이 5개 아래로 줄거나 세 바퀴에 한 번, 새 앱·새 불만을 찾아
   `research/` 에 덧붙이고 BACKLOG 에 올린다. 같은 출처를 다시 읽지 않는다.

## 하지 않는 것

- **주문을 내는 기능.** 이 앱은 조회 전용이다. 매매는 토스 앱으로 넘긴다.
- 토스 앱키·접속 암호·`web/config.json`·`web/data/` 를 커밋하거나 출력하지 않는다.
- 사용자가 **일부러 뺀 것**을 되살리지 않는다: 랭킹 탭, TWR·MDD·실현손익 추정, 비교 탭 당겨서 새로고침,
  자산 추이 일/주/월 토글, 새로고침 단추.
- 화면 배치·제스처를 한 번에 크게 바꾸지 않는다. 새 기능은 **기본 꺼짐 또는 눈에 덜 띄는 자리**에서 시작한다.
- 알림은 기본 꺼짐.
- 확인 못 한 것을 됐다고 적지 않는다. 기기에서만 볼 수 있는 것은 `LOG.md` 에 **"기기 확인 필요"**로 남긴다.

## 확인의 한계

이 PC 에는 에뮬레이터가 없다. 컴파일과 서버 검사까지만 자동이고, **화면이 실제로 어떻게 보이는지는
사용자 폰에서만** 알 수 있다. 그래서

- 레이아웃을 크게 흔드는 변경은 작게 쪼개 한 번에 하나씩 내보낸다.
- 릴리스 노트에 "이번에 바뀐 것 · 봐 주면 좋은 것"을 적는다.
- 사용자가 이상하다고 한 것은 BACKLOG 맨 위로 올린다.

## 배운 것 (바퀴를 돌며 추가)
